# SRS — 앱이 떠 있을 때 받은 경로 열기 (이슈 #80)

| 항목 | 내용 |
|---|---|
| 상태 | 검수 통과(v1.3) |
| 근거 | 요구사항 정리 v1 (이슈 #80), 오너 결정 2026-11-19 (이슈 #80 코멘트, 요구사항 3) |

## 1. 목적과 범위

### 1.1 목적
앱(`FileListActivity`)이 이미 떠 있을 때 다른 앱·바로 가기가 경로를 담은 Intent로 화면을 열어도, 그 경로가 화면에 나타나게 한다(요구사항 2).

### 1.2 원인 (코드 확인, 요구사항 1)
1. `FileListActivity`에 `launchMode`가 없어 기본값 `standard`다(`app/src/main/AndroidManifest.xml:64-68`). `onNewIntent` 재정의도 없다(`FileListActivity.kt:23-73`. 저장소 전체 `grep onNewIntent` 결과 0건).
2. 화면을 연 Intent는 화면을 처음 만들 때 한 번만 읽는다.
   - `FileListActivity.onCreate`가 `savedInstanceState == null`일 때만 `FileListHostFragment.Args(intent)`를 넘긴다(`FileListActivity.kt:31-33`).
   - 호스트는 그 Intent를 창 1에만 넘긴다(`FileListHostFragment.kt:119-124`).
   - 창은 이동 기록이 없을 때만 Intent에서 시작 경로를 정한다(`FileListFragment.kt:295-354`).
   - 그래서 이미 있는 화면은 나중에 온 Intent를 반영할 길이 없다.
3. `am start`·실행기 바로 가기처럼 `FLAG_ACTIVITY_NEW_TASK`를 단 Intent가 오면 시스템은 기존 작업(task)을 앞으로 가져온다. 그때 동작은 다음과 같다.
   - (a) Intent가 작업을 처음 만든 Intent(root intent)와 같으면(`Intent.filterEquals`: action·data·type·component·category) 새 화면을 만들지 않는다. 앱이 이미 맨 앞이면 `am start`가 `Warning: Activity not started, intent has been delivered to currently running top-most instance.`를 출력하고 화면은 그대로다. #69 재현 절차(`_workspace/wo/69-stale-archive/avd.sh`의 `openzip` 반복, 같은 `t.zip` VIEW를 두 번 보냄)가 이 경우다.
   - (b) root intent와 다르면 표준 모드라 같은 작업 위에 `FileListActivity`를 **새로 하나 더 쌓는다**. 경로는 보이지만 두 창이 모두 새로 시작한다. 창 2는 기본 디렉터리에서 열리고(#2 REQ-2-19), 뒤로 가기로 맨 위 폴더까지 올라가면 이전 화면으로 돌아간다.
   - (a)·(b)의 시스템 쪽 판단은 AOSP `ActivityStarter`의 작업 재사용 규칙에 따른다. 기기 재현은 하지 않았다(미확인). 그래서 HLD는 (a)·(b) 어느 쪽이 맞든 REQ-80-01을 만족하는 방식을 골라야 한다(결과에 기대는 방식이면 HLD 확정 전에 V0를 먼저 한다). V0는 개발팀이 LLD를 시작할 때 고치기 전 빌드로 확인하며, (a)에서 표준 모드인데도 `onNewIntent`가 불리는지도 로그로 본다(4.2 V0).
4. `FLAG_ACTIVITY_NEW_TASK` 없이 다른 앱이 보낸 Intent는 보낸 앱의 작업에 새 `FileListActivity`를 만든다(미확인, V0). 이 앱의 작업과 따로 떠서 지금도 경로가 보인다. 그 화면은 이 앱 작업의 "떠 있는 화면"(1.3)이 아니므로 REQ-80-01이 적용되지 않고, 지금처럼 보낸 앱 작업에 둘째 인스턴스가 생긴다. 이 SRS가 바꾸는 대상이 아니다.

### 1.3 용어
| 용어 | 뜻 |
|---|---|
| 경로 Intent | 선택 모드가 아니면서 열 경로를 담은 Intent. `Intent.extraPath`로 경로가 나오는 `ACTION_VIEW`(폴더·압축 파일, `IntentPathExtensions.kt:21-32`), 그리고 `ACTION_VIEW_DOWNLOADS`(`FileListFragment.kt:335-340`, 실행기 바로 가기 `res/xml/shortcuts.xml`)다. 시작 경로를 정하는 규칙은 `FileListFragment.kt:296-350`의 선택 모드가 아닌 갈래와 같다. |
| 선택 모드 Intent | `ACTION_GET_CONTENT`·`ACTION_OPEN_DOCUMENT`·`ACTION_CREATE_DOCUMENT`·`ACTION_OPEN_DOCUMENT_TREE`(`FileListHostFragment.kt:276-281`) |
| 둘러보기 화면 | 선택 모드가 아닌 `FileListActivity`(두 창 사용, #2) |
| 활성 창 | #2의 활성 창(`DualPaneViewModel.activePane`). 한 창 모드에서는 보이는 창 |
| 떠 있는 화면 | 같은 작업의 맨 위에 있는 기존 `FileListActivity` 인스턴스. 작업이 화면 맨 앞에 있든, 뒤에 있다가 Intent 때문에 앞으로 오든 같다 |

### 1.4 범위
- 범위 안: 떠 있는 둘러보기 화면이 경로 Intent를 받았을 때의 동작.
- 범위 밖:
  - 새 Intent 종류 추가(요구사항 정리 v1).
  - 선택 모드 동작 변경(요구사항 4).
  - #11 복원 규칙 변경(요구사항 4).
  - 홈 화면 폴더 바로 가기의 `FLAG_ACTIVITY_CLEAR_TASK` 동작(A3).

## 3. 비기능 요구사항
- **지원 API**: minSdk 23~ 전 범위에서 같은 동작이어야 한다. 시스템 작업 재사용 규칙의 버전 차이는 HLD 위험 항목이다.
- **성능·스레드**: 받은 Intent 판단은 메인 스레드에서 입출력 없이 즉시 끝난다. 목록 읽기는 기존처럼 비동기다(REQ-80-04).
- **권한**: 새 권한·설정 키·영구 저장이 없다. 저장소 권한 안내는 지금과 같다.
- **루트/비루트·원격·압축**: 경로 종류에 따라 규칙을 나누지 않는다. 접근 실패는 REQ-80-04로 알린다.
- **접근성**: 새 UI·문구가 없다. 활성 창 표시는 #2 그대로다.

| A2 | 뒤로 가기(REQ-80-03)는 한 창 앱의 자연스러운 동작인 "앱 안에서 그 경로로 옮긴 것과 같음"으로 정했다. 이 앱은 폴더 이동 기록(방문 순서)을 두지 않고 뒤로 가기는 상위 폴더 이동이다(`TrailData.kt:43-49`). 그래서 받기 전 위치로 돌아가는 동작을 새로 만들면 앱 안 다른 이동과 어긋난다. 지금 (b)(새 화면을 쌓음)에서는 맨 위 폴더에서 뒤로 가기가 이전 화면으로 돌아갔지만, 바뀐 뒤에는 지금 맨 위에서와 같이 화면을 떠난다. 오너 결정 A1의 직접 귀결이다. | 오너 지시(2026-11-19: "자연스러운 한 창 동작을 제안"), `FileListFragment.kt:274-285` |
| A3 | 앱 안 "바로 가기 만들기"로 만든 홈 화면 폴더 바로 가기는 `FLAG_ACTIVITY_CLEAR_TASK`로 작업을 새로 시작하게 만들어져 있다(`FileListFragment.kt:1615-1616`). 이미 홈 화면에 고정된 바로 가기는 그 Intent를 그대로 저장하고 있어 앱 쪽에서 바꿀 수 없다. 그래서 이 동작은 그대로 둔다(REQ-80-06). 이 SRS는 작업을 지우지 않는 경로 Intent에만 적용한다. | 코드, Android 고정 바로 가기 동작 |
| A4 | 경로가 없는 `ACTION_VIEW`를 받았을 때 화면을 바꾸지 않는 것(REQ-80-04)은 이미 떠 있는 화면을 지키는 쪽이다. 새로 열 때 기본 디렉터리로 가는 동작은 열 화면이 없어서 생긴 것이다. | 요구사항 2("연 경로가 나타난다")는 경로가 있을 때만 해당 |
| A5 | 떠 있는 화면 위에 이 앱의 다른 화면(설정·저장소 편집 등)이 있으면, 그 경우의 동작은 지금과 같다. 작업 재사용 규칙상 `FileListActivity`가 맨 위가 아니기 때문이다. 오너 결정의 "현재 떠 있는 창"은 보이는 파일 목록 화면이다. | 오너 결정 문장, 1.2 ③ |
