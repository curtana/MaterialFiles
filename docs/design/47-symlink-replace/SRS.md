## 1. 목적과 범위
같은 이름이 있는 곳에 심볼릭 링크를 '바꾸기'로 복사하면 기존 항목을 지우고 링크를 다시 만드는 데 성공해도 원래 예외(`FileAlreadyExistsException`)가 던져진다(develop 7cf16b7 `provider/linux/LinuxCopyMove.kt:158-179` — 다시 만들기 성공 뒤 `return`이 없어 178행의 `throw`로 떨어짐). `filejob/FileJobs.kt:1377-1419`는 이 예외를 다시 충돌로 처리하므로 충돌 창이 다시 뜨고, '모두 적용'이면 `FileJobs.kt:1391-1394`의 재시도가 취소할 때까지 반복된다. 뒤따르는 속성 단계(`LinuxCopyMove.kt:184-`)도 실행되지 않는다.

이 문서는 이 결함 수정만 다룬다. 대상은 심볼릭 링크를 복사하는 세 백엔드의 복사 함수다.
- 로컬(Linux): `provider/linux/LinuxCopyMove.kt` `copy`
- SFTP: `provider/sftp/SftpCopyMove.kt` `copy`
- SMB: `provider/smb/SmbCopyMove.kt` `copy`

## 3. 비기능 요구사항
- 지원 API: minSdk 23 이상 전체. 새 권한·설정·문자열을 추가하지 않는다.
- 루트/비루트: 로컬 복사는 루트 모드에서도 같은 `LinuxCopyMove`를 쓰므로 같은 규칙이 적용된다. 루트 원격 프로세스 자체의 문제는 #43 범위다.
- 링크가 아닌 항목(일반 파일·폴더)의 복사 동작, 이동(`move`) 동작, 충돌 처리(`FileJobs.kt`)는 바꾸지 않는다.

## 4. 제약과 가정
- '바꾸기'가 선택된 경우에만 대상을 지운다. '바꾸기'가 아니면 지금처럼 충돌로 알린다(`LinuxCopyMove.kt:51-53`, `SftpCopyMove.kt:61-63`, `SmbCopyMove.kt:56-58`).
- 폴더 위에 링크(파일 아님)를 바꾸는 경우는 `FileJobs.kt:1382-1385`가 먼저 막으므로 이 문서의 범위 밖이다.
- 범위 밖: 네트워크 복사가 링크를 따라가는 것·속성 맞추기 규칙·순환 방지(#55), 확장 속성 값을 대상에서 읽는 문제(#48), 루트 원격 프로세스(#43), '바꾸기' 경고 문구(#54).
- 가정: 결함은 코드 읽기로 확인했고 실행 재현은 아직 없다. REQ-47-05의 재현에서 증상이 다르면 구현 전에 SRS를 다시 본다.
