## 1. 목적과 범위

### 1.1 목적
지금 진행 중인 파일 작업을 멈출 수 있는 곳은 알림의 "취소" 버튼뿐이다(`filejob/FileJobs.kt:138-147` → `FileJobReceiver` → `FileJobService.cancelJob`, `FileJobService.kt:218-223`). 알림을 꺼 두었거나 무음이면 앱 안에서 작업을 멈출 방법이 없다. 파일 목록 화면의 툴바 메뉴에서 작업 목록을 열어 작업마다, 또는 한꺼번에 취소할 수 있게 한다. 취소한 작업이 대상 위치에 남긴 깨진 파일은 지운다.

### 1.2 범위
- 파일 목록 화면 툴바 메뉴의 "파일 작업" 항목과, 그 항목이 여는 작업 목록 창(줄마다 종류·대상 이름·진행률·취소 버튼, 그리고 "모두 취소").
- 목록에 보여 줄 작업별 정보(종류·대상 이름·진행률)와 끝난 방식(완료·취소됨·실패)을 화면 쪽에 알리는 통로. #30의 상태 통로를 넓힌다.
- 취소된 작업이 쓰던 중이던 대상 파일의 삭제와, 지우지 못했을 때 사용자에게 알리기(요구사항 6).
- 취소한 작업이 실제로 멈추게 하기(요구사항 3, v4. 줄 취소·모두 취소·알림 취소 공통).
- 사용자가 취소하지 않았는데 `InterruptedIOException`으로 끝난 작업을 알리고 "실패"로 표시하기(요구사항 8, v6, #39).
- 접근성, 밝은·어두운 테마, RTL.

### 1.3 범위 밖 (요구사항 정리 v2 "범위 밖")
- 작업 일시정지·재개, 순서 바꾸기.
- 끝난 작업의 이력 보관(목록을 다시 열면 사라짐).
- 정리 실패 알림을 다시 볼 곳(이력·영구 표시)과 알림 추가(요구사항 v5). 토스트와 줄 표시를 놓치는 경우는 사용자 몫이다.
- 네트워크 시간 초과로 끝난 작업의 오류 창·다시 시도, 시간 초과의 실제 네트워크 재현(요구사항 v6).
- 기존 알림 변경(알림의 내용·취소 버튼·갱신 주기 모두). 다만 알림 취소를 누른 **뒤** 작업이 멈추는 동작은 고친다(요구사항 v4 3, REQ-36-05).
- 파일 하나만 취소하거나 건너뛰는 기능(요구사항 v4 3). 처리 속도 표시(요구사항 v4 2).
- "바꾸기"의 기존 파일 선삭제를 임시 이름 복사로 바꾸는 일: #42(v1.7.5). 그 전까지의 동작은 4.1 L1.
- 파일 목록 밖 화면(다른 앱이 연 파일 고르기·저장 창 등)에서 목록 열기.
- 취소를 일으키는 수단의 교체. `Future.cancel(true)` 끼어들기(`FileJobService.kt:80`)를 그대로 쓴다. v4가 승인한 범위는 그 끼어들기가 소비되어도 작업이 멈추도록 표시를 더하는 것(REQ-36-05)과 남은 조각 삭제·실패 알림이다.
- #30 툴바 표시(선 사람)의 동작 변경. 끝난 방식 구분을 넓혀도 #30의 묶음 결과 규칙(취소도 "실패" 자세, `docs/design/30-job-runner/SRS.md` REQ-30-04)은 그대로다.

### 1.4 용어
| 용어 | 뜻 |
|---|---|
| 파일 작업 | `FileJobService`의 시작 함수(`FileJobService.kt:134-215` — `archive`·`copy`·`create`·`delete`·`move`·`installApk`·`open`·`rename`·`restoreSeLinuxContext`·`save`·`setGroup`·`setMode`·`setOwner`·`setSeLinuxContext`·`write`)로 시작된 `FileJob` 하나. #30 SRS 1.4와 같다. |

| 대기 중 | 시작 함수가 불렸으나 서비스가 아직 만들어지지 않아 대기 목록(`pendingJobs`, `FileJobService.kt:116`, 추가 `:129`)에 있는 작업. 서비스가 만들어지면 곧바로 실행으로 넘어간다(`:43-45`). 실행기는 캐시 스레드 풀이라(`:32`) 작업끼리 줄 서서 기다리는 일은 없다. |

| 대상 파일 | 작업이 새로 쓰는 파일: 복사·이동·압축 풀기의 목적지 파일, 압축의 압축 파일, 저장의 목적지 파일, 쓰기의 파일. |

| 깨진 파일(남은 조각) | 취소 때문에 끝까지 쓰이지 못한 대상 파일. 끝까지 다 쓴 대상 파일과 만들어 둔 폴더는 깨진 파일이 아니다(가정 A3). |

### 1.5 지금 동작(기준선) — 취소 시 대상 파일

## 3. 비기능 요구사항

### 3.1 환경
- 지원 API: minSdk 23 ~ targetSdk 36(`app/build.gradle:34,37`).
- 권한: 새 권한을 추가하지 않는다(`Minimize_Permissions`).
- 백엔드: 로컬(일반·루트 모드), 문서 공급자(SAF), 압축 파일 안(압축 풀기 원본), SMB·SFTP·FTP·WebDAV 모두 REQ-36-05·10·11·16을 만족한다(한계는 4.1.1). 수동 확인은 적어도 로컬, 루트(가능한 기기), SFTP, SMB 네 가지로 한다. 백엔드마다의 정리 경로는 HLD에서 코드로 근거를 든다.
- 새 런타임 의존성을 추가하지 않는다(PROCESS_ROLES 10장). 목록 화면은 이미 있는 AndroidX·Material 구성요소로 만든다.

### 3.2 성능·자원
- 진행 값 알림은 알림을 만드는 곳과 같은 시점에만 보낸다(작업마다 0.5초에 한 번 이하, `FileJobs.kt:154`. 훑기는 HLD K7의 전용 거르기로 지킨다). 작업 스레드에 새 입출력을 더하지 않는다.
- 메인 스레드에서 입출력을 하지 않는다(`Stability_ANR`). 대상 이름은 경로 객체에서 입출력 없이 얻는다.
- 목록 창이 닫혀 있을 때 화면 쪽에 남는 상태는 진행 중 작업의 정보뿐이다. 끝난 작업의 정보는 목록 창이 열려 있을 때만 그 창이 가진다(이력 보관 없음, 1.3).

### 3.3 접근성
- 취소 버튼은 아이콘 버튼이어도 설명을 가진다: "<대상 이름> 취소" 꼴로 어느 작업인지 말한다(`Content_Description` 필수, `A11Y-2` 권장). "모두 취소"·"닫기"는 글 버튼이다.
- 터치 대상: 줄의 취소 버튼, "모두 취소", "닫기", 메뉴 항목 모두 48dp 이상(`Touch_Target_Size` 필수).
- 상태 구분은 색만으로 하지 않는다: 끝난 방식은 글("완료"·"취소됨"·"실패")로 보인다(`A11P-2` 권장). 비활성 취소 버튼은 접근성 서비스에 "사용할 수 없음"으로 드러난다.
- 진행률 막대는 낭독기에 현재 값을 드러내되, 갱신마다 소리 내어 알리지 않는다(초점이 있을 때 읽는 수준). 끝난 방식으로 바뀐 줄은 초점 이동 없이 한 번 알린다(규격 근거는 5장, 원문 판독 필요 — #30 REQ-30-12와 같은 근거 수준). 확인은 수동이다: TalkBack을 켜고 목록을 연 채 큰 복사 → 진행 중 반복 낭독 없음 → 끝날 때 끝난 방식 한 번 낭독.
- 대비: 글자는 4.5:1 이상(`Visual_Contrast` 필수, `A11Y-3` 권장). 진행 막대·아이콘은 3:1 이상. 기존 화면의 목록 글 스타일과 테마 색 속성을 쓴다.

### 3.4 테마
- 밝은·어두운 테마, Material 3 켬·끔, 검은 어두운 테마 모두에서 3.3의 대비를 만족한다(`Theme_Support` 필수). 앱의 기존 화면과 같은 테마 속성을 쓰므로 테마 색을 바꾸면 따라간다.

### 3.5 RTL
- 줄 안 배치는 start/end로 한다(`RTL-1`): 글은 시작 쪽, 취소 버튼은 끝 쪽. 목적지를 가리키는 화살표 등 방향이 있는 기호는 RTL에서 뒤집는다(`RTL-2`). 확인은 "RTL 레이아웃 방향 강제"(`RTL-4`).

### 4.2 제약
- C-1: 취소되지 않은 작업의 분기·반환값·오류 창 선택지를 바꾸지 않는다. **유일한 예외**는 `InterruptedIOException`으로 끝날 때의 토스트다(REQ-36-17, 요구사항 v6). 작업 본문에 더하는 것은 진행 값을 화면 쪽에 알리는 줄, 끝난 방식을 돌려주는 최소 변경, 취소 표시 점검(REQ-36-05), 오류·충돌 창 "취소"에서 취소 표시 켜기(REQ-36-08), 정리 실패 기록(REQ-36-16)뿐이다. 백엔드(`provider/`)의 지우기 호출·조건·순서는 바꾸지 않고, 실패·결과 모름을 알리는 통로만 더한다. 예외로 `Client.copyFile`의 정리 앞에서 끼어들기 표시를 지우는 한 줄을 더한다(HLD K14): 복사가 이미 실패한 경로이고 작업의 멈춤은 취소 표시가 맡으므로 취소되지 않은 작업에는 영향이 없다.
- C-2: 알림은 그대로다(1.3).
- C-3: 새 의존성 없음(3.1).
- C-4: 이 기능은 #30 상태 통로의 공개 함수 모양(`onJobFinished(id, isSuccessful)`, `runOn(): Boolean`)을 넓힐 수 있다. 넓히더라도 #30의 동작(REQ-36-09)과 테스트는 그대로 통과해야 한다.
