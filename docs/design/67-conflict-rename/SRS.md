## 1. 목적과 범위

### 1.1 목적
충돌 창(`filejob/FileJobConflictDialogFragment.kt`)에서 새 이름을 입력한 뒤 화면을 돌리면(또는 창이 다시 만들어지면) 입력한 이름이 원래 이름으로 돌아가고 긍정 버튼이 "이름 바꾸기"에서 "교체"/"합치기"로 돌아온다. 회전 전 이름 바꾸기를 의도한 사용자가 그대로 긍정 버튼을 누르면 교체가 되어 기존 파일을 잃을 수 있다(이슈 #67 재현 절차).

원인(코드):
- 저장 상태가 `allCheck`만 담는다: `onSaveInstanceState`(`FileJobConflictDialogFragment.kt:64-68`), `State(isAllChecked)`(`:351-354`).
- 창을 다시 만들 때 이름 입력란에 원래 이름을 다시 넣는다: `binding.nameEdit.setTextWithSelection(targetFileName)`(`:121-122`).
- 창 내용 뷰(`binding.root`)는 `onStart`에서야 창에 붙는다(`:253-263`).

주석(추정, HLD에서 확정): 위 셋째 사실 때문에 Android의 창 뷰 계층 자동 복원도 이 뷰들에 미치지 않는다고 본다.

### 1.2 범위
- 충돌 창의 저장·복원 상태에 "새 이름"과 그 이름 입력란 펼침 상태를 더한다.
- 복원 뒤 긍정 버튼 글자와 "모든 파일에 적용" 체크의 사용 가능 여부를, 새 이름이 있을 때 회전 전과 같은 규칙(`:123-132`)으로 맞춘다.

### 1.3 범위 밖
- 충돌 창의 다른 동작·문구 변경(요구사항 정리 v1 "범위 밖").
- 커서 위치·선택 영역, 입력란 포커스, 화면 키보드 표시 여부의 보존. 필수가 아니다(4장 가정 A2).
- 이름 입력란 펼침 상태만 바뀌고 새 이름이 없는 경우의 보존(REQ-67-02, 지금과 같음).

### 1.4 용어
| 용어 | 뜻 |
|---|---|
| 새 이름이 있음 | `hasNewName()`(`:244-251`)이 참: 입력란 글자가 비어 있지 않고 대상의 원래 이름과 다르다 |
| 재생성 | 회전·화면 크기 변경·다크 모드 전환 등 구성 변경, 또는 백그라운드에서 프로세스가 정리된 뒤 복원으로 창 Fragment가 저장 상태(`savedInstanceState`)를 받아 다시 만들어지는 것 |

### 2.1 AVD 확인 절차 (V1)
1. AVD(실제 기기 아님)에서 `a.txt`가 있는 폴더로 같은 이름 `a.txt`를 복사해 교체 충돌 창을 띄운다. 합치기 충돌은 같은 이름 폴더를 그 폴더가 있는 곳으로 복사해 띄운다.
2. 이름 입력란을 펼쳐 `b.txt`로 바꾼다(버튼 "이름 바꾸기"). 화면을 회전한다 → REQ-67-01을 확인하고 긍정 버튼을 눌러 `b.txt`가 생기는지 본다.
3. 이름을 바꾸지 않은 채(펼치지 않음 / 펼치기만 함 / 비움) 회전한다 → REQ-67-02.
4. 회전 밖 재생성: (a) Activity 파괴 — 개발자 옵션 "활동 유지 안 함"을 켜고 2를 반복하되 회전 대신 홈으로 나갔다가 최근 앱에서 돌아온다. (b) 프로세스 정리 — 2의 상태에서 홈으로 나간 뒤 `adb shell am kill me.zhanghai.android.files`로 정리하고 최근 앱에서 돌아온다. 둘 다 결과는 2와 같아야 한다. (b)에서 작업 서비스가 함께 정리되어 창이 다시 뜨지 않으면 그 사실을 기록하고 (a)만으로 갈음한다.
5. en·ko 각각, 교체 충돌에서 재생성 뒤에도 경고가 보이는지 함께 본다(REQ-67-03).

## 3. 비기능 요구사항
- **API 레벨**: minSdk 그대로, 새 API 없음. 저장 상태는 기존 `ParcelableState`/`putState`·`getState`(`util/`) 방식을 쓴다.
- **권한·백엔드**: 해당 없음. 모든 백엔드가 같은 창을 쓴다.
- **저장 크기**: 파일 이름 하나와 플래그 몇 개뿐이라 저장 상태 크기 제한(`TransactionTooLargeException`)과 무관하다.
- **검증 환경**: AVD(예: `Medium_Phone_API_36`)에서만 확인한다. 실제 기기는 쓰지 않는다.

## 4. 제약과 가정
- A1: 새 이름은 재생성 시점의 입력란 글자 그대로 저장한다. 이름의 유효성(금지 문자 등)은 지금처럼 검사하지 않는다.
- A2: 커서·선택·포커스·키보드는 보존하지 않는다. 새 이름이 복원되면 버튼 글자로 상태가 드러나므로 요구사항 1을 충족한다. 이 가정은 요구사항 정리 v1에 명시되어 있지 않아 HLD 검수에서 과하면 지적받는다.
- A3: 새 이름이 있는데 입력란을 접어 둔 상태(펼쳤다가 입력 후 접음)도 REQ-67-01(b)대로 접힌 채 "이름 바꾸기"로 복원한다. 회전 전 화면과 같기 때문이다.
- A4: 재생성 전 상태는 이 Fragment의 저장 상태만으로 복원한다. 작업 쪽(`FileJobs.kt`)과 `FileJobConflictDialogActivity`는 바꾸지 않는다.
