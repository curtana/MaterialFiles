## 1. 목적과 범위

### 1.1 목적
지금은 파일 목록 화면이 하나뿐이라(`FileListActivity.kt:30-32`가 `FileListFragment` 하나만 붙인다) 복사·이동하려면 "복사 → 대상 폴더로 이동 → 붙여넣기"를 거쳐야 한다. 파일 목록 창을 두 개 두어 두 폴더를 오가며 바로 복사·이동할 수 있게 한다.

### 1.2 범위
- 파일 목록 화면(`FileListActivity`)의 두 창 구성, 너비에 따른 표시 방식, 창 전환 제스처, 활성 창, 반대쪽 창으로 복사·이동, 공유 복사 목록, 복사·이동 확인 창, 현재 위치 표시, 시작 경로.
- 파일 작업 실행(`filejob/`)과 파일 시스템(`provider/`)의 동작은 바꾸지 않는다. 복사·이동은 지금처럼 `FileJobService.copy/move`(`FileJobService.kt:126-140`)로 실행한다.

### 1.3 범위 밖 (요구사항 정리 v1 "범위 밖")
- 창 3개 이상, 탭.
- 끌어다 놓기(drag & drop)로 복사·이동.
- 창 경로의 영구 저장(앱 재시작 뒤 복원).

### 1.4 용어
| 용어 | 뜻 |
|---|---|
| 창 1·창 2 | 각각 독립된 파일 목록(경로·뒤로 가기 기록·선택 상태를 따로 가짐). 창 번호는 고정이며 두 창 모드에서 창 1이 시작(start) 쪽, 창 2가 끝(end) 쪽에 놓인다. |
| 한 창 모드 / 두 창 모드 | 한 번에 한 창만 보이는 상태 / 두 창이 나란히 보이는 상태. |
| 활성 창 | 상단 메뉴(툴바 메뉴·탐색 서랍의 항목)와 복사·이동 명령의 기준이 되는 창. 한 창 모드에서는 보이는 창이 활성 창이다. |
| 상단 메뉴 | 툴바의 메뉴 항목(검색·보기·정렬·새로 고침 등)과 탐색 서랍. 이 중 창의 상태에 작용하는 항목(검색, 새로 고침, 위로·경로로 이동, 전체 선택, 탐색 서랍의 경로 이동, 경로별 보기·정렬 설정의 대상 경로)이 활성 창 기준이다. 전역 설정 항목(숨김 파일 표시, 경로별이 아닌 보기·정렬)은 지금처럼 설정 값을 바꾸며 두 창에 함께 적용된다(4.2 C-2). 툴바를 창마다 둘지 하나를 공유할지는 HLD에서 정한다. 어느 쪽이든 이 SRS의 요구(REQ-2-09)는 "메뉴가 작용하는 창 = 활성 창"이다. 이 SRS의 검증 절차는 툴바 배치와 무관하게 쓴다. |
| 반대쪽 창 | 활성 창이 아닌 창. |
| 파일 목록 영역 너비(W) | 두 창이 들어갈 영역의 실제 너비(dp). 고정 메뉴(`PersistentDrawerLayout`의 탐색 서랍)가 펼쳐져 있으면 그 너비를 뺀 값이다. |
| 고정 메뉴 | 짧은 변 600dp 이상 + 가로 화면에서 쓰이는 펼친 채로 두는 탐색 서랍(`res/layout-sw600dp-land/file_list_fragment_include.xml:24-38`). 그 밖의 화면은 열고 닫는 서랍(`res/layout/file_list_fragment_include.xml:10-55`)을 쓴다. |
| 복사 목록 | "복사/잘라내기"로 모은 항목과 복사·이동 구분(`PasteState.kt:9-12`). |
| 오른쪽→왼쪽 쓸기 | 화면 위를 손가락으로 오른쪽에서 왼쪽으로 가로로 미는 동작(왼쪽→오른쪽 배치 기준, RTL은 4.1 가정 A2). |

## 3. 비기능 요구사항

### 3.1 환경
- 지원 API: minSdk 21 ~ targetSdk 34(`app/build.gradle:34,37`). 제스처 내비게이션의 가장자리 영역은 API 29 이상에서 시스템이 알려 준다. API 28 이하에서는 시스템 가장자리 제스처가 없으므로 REQ-2-11(a)은 해당 없음.
- 권한: 새 권한을 추가하지 않는다.
- 루트/비루트, 로컬/원격(SMB·SFTP 등)/압축 파일 경로 모두 지금과 같은 방식으로 각 창에서 열 수 있어야 한다(창이 둘이 될 뿐 경로 종류별 처리는 기존 코드를 쓴다).
- 오프라인: 영향 없음.

### 3.2 수동 확인 기기 구성
| 구성 | 예 | 기대 표시 |
|---|---|---|
| C1 | 폰 세로(너비 약 360~411dp) | 한 창 |
| C2 | 폰 가로(너비 600dp 이상, 짧은 변 600dp 미만 → 열고 닫는 서랍) | 두 창 |
| C3 | 폰 분할 화면(앱 너비를 600dp 전후로 조절) | 너비에 따라 바뀜 |
| C4 | 짧은 변 600dp 이상 가로, 화면 너비 600~919dp(고정 메뉴 최대 너비 320dp: `res/values/dimens.xml:26`) — 에뮬레이터 해상도·밀도 조절로 만든다 | 고정 메뉴 펼침 → 한 창, 접음 → 두 창 |

C4 만드는 법(예): 태블릿 에뮬레이터에서 `adb shell wm size 1700x1300`, `adb shell wm density 320`(약 850×650dp) 뒤 가로로 둔다. 화면에 고정 메뉴가 보이면 sw600dp-land 배치가 적용된 것이다. 확인 뒤 `adb shell wm size reset`, `adb shell wm density reset`.

### 3.3 접근성
- 활성 창 구분(REQ-2-08)은 색 차이만으로 하지 않는다(테두리·굵기·글자 표시 같은 형태 차이를 함께 쓴다).
- 창 번호·활성 여부 표시(REQ-2-17)는 화면 낭독기(TalkBack)가 읽을 수 있는 글자여야 한다.
- 쓸기 제스처만으로 창을 바꿀 수 있는 것이 접근성 규격에 맞는지는 원문 판독 필요(5장, 4.3 Q3).

### 3.4 성능·자원
- 두 창은 각자 목록을 불러온다. 창 하나일 때보다 디렉터리 감시·목록 적재가 최대 두 배가 될 수 있다. 보이지 않는 창(한 창 모드)도 상태를 유지해야 하므로(REQ-2-02) 목록을 버리지 않는다.
- 쓸기 인식 때문에 세로 스크롤 시작이 눈에 띄게 늦어지지 않아야 한다: 가로 이동이 시스템 터치 슬롭(`ViewConfiguration.scaledTouchSlop`)을 넘고 세로 이동보다 클 때만 창 전환으로 판단한다.

### 4.2 제약
- C-1: 파일 작업 백엔드(`filejob/`, `provider/`)는 바꾸지 않는다. 확인 창은 작업을 시작하기 전 UI 단계에 둔다.
- C-2: 기존 화면 동작(정렬·보기 방식·숨김 파일·검색·선택 모드 등)은 각 창 안에서 지금과 같아야 한다. 보기 방식·정렬은 설정 값(경로별 설정 포함)이라 두 창이 같은 설정을 읽는다 — 기존과 같다.
- C-3: 저장소에 단위 테스트 소스·의존성이 아직 없다(`app/src`에 `main`만 있음, `app/build.gradle`에 `testImplementation` 없음). REQ-2-03 판단 함수의 단위 테스트를 넣으려면 테스트 의존성 추가에 PROCESS_ROLES 10장 라이브러리 승인이 필요하다. 승인되지 않으면 수동 확인만으로 검증한다.
- C-4: 새 사용자 문자열(창 이름, 명령, 확인 창)은 기본(`values/`) 문자열로 추가한다. 다른 언어 번역은 기존 관례대로 이 범위에서 채우지 않는다(한국어 `values-ko/`는 추가 권장).
