## 1. 목적과 범위

### 1.1 목적
압축 파일 안 목록을 보는 중에 원본 압축 파일이 지워지면, 앱 프로세스가 살아 있는 동안 그 목록이 그대로 남는다. 다시 열어도(VIEW intent가 기존 작업을 앞으로 가져올 뿐인 HOT 시작) 예전 항목이 보이고, 당겨서 새로 고쳐야 `NoSuchFileException`이 나온다. 원인은 두 가지다(이슈 #69 원인 조사).
1. 압축 파일 목록에는 변경 감시가 없다. `ArchiveFileSystemProvider.observe()`가 `UnsupportedOperationException`을 던지고(`provider/archive/ArchiveFileSystemProvider.kt:279-281`) `PathObserver`가 이를 무시한다(`filelist/PathObserver.kt:33-35`). 원본이 지워져도 다시 읽기가 일어나지 않는다.
2. 다시 읽기가 실패해도 이전 목록을 유지한다(`filelist/FileListLiveData.kt:80` `Failure(valueCompat.value, e)`, #29 B3 정책 REQ-29-06(b)). 감시만 붙이면 예전 항목 + 부제목 "Error" + 토스트가 된다.

프로세스를 새로 띄우면(COLD) 첫 읽기가 실패해 지금도 오류 화면이 나온다(3/3).

### 1.2 범위
- 압축 파일 안 목록의 변경 감시: 원본 압축 파일의 변경을 그 압축 안 목록의 변경으로 전달한다(2.1).
- 목록 읽기가 "보던 폴더(또는 압축 파일) 자체가 없음"(`NoSuchFileException`)으로 실패할 때의 표시: 모든 경로(로컬·루트·SAF 문서·콘텐츠·FTP·SFTP·SMB·WebDAV·압축)(2.2).

### 1.3 범위 밖
- 압축 파일 처리 전반의 재설계(요구사항 정리 v1).
- `NoSuchFileException` 밖의 다시 읽기 실패 — #29 B3 그대로(2.3).
- 지워진 뒤 같은 경로에 다시 만들어진 파일·폴더를 자동으로 감지하는 것(4.2 L1).
- 감시를 지원하지 않는 파일 시스템에 감시를 더하는 것(4.2 L2).
- 검색 결과 목록(`SearchFileListLiveData`) — 감시가 없고 #29에서도 범위 밖이다.
- 지워진 폴더를 보던 창을 자동으로 상위 폴더로 옮기는 것.

## 2. 기능 요구사항

용어: **다시 읽기** = 목록이 이미 있는 창에서 같은 경로를 다시 읽는 모든 계기(#29의 자동 T1~T3, 명시 T4~T6). **없음 실패** = 읽기가 `java8.nio.file.NoSuchFileException`(또는 그 하위 클래스)로 끝난 것.

### 2.1 압축 파일 목록의 변경 감시

| ID | 요구사항 | 우선순위 | 검증 방법 |

## 3. 비기능 요구사항
- 지원 API: minSdk 23~(지금과 같음). 권한·루트 여부와 무관.
- 성능: 압축 파일 하나를 볼 때 원본 파일 감시 하나가 더 생긴다(로컬이면 inotify watch 하나). 원본이 쓰이는 동안에는 알림마다(1000ms로 묶임, `PathObserver.kt:61`) 압축 항목을 다시 읽는다 — HLD 위험에 적는다.
- 접근성: 오류 화면은 기존 요소이므로 TalkBack 동작은 지금 첫 읽기 실패와 같다. 새 안내를 더하지 않는다.
- 시험 환경: 수동 확인은 AVD에서만 한다. **실기기(오너 태블릿·휴대폰)에는 설치하지 않는다.**

## 4. 제약과 가정

### 4.1 제약·가정
- **C-1**: `FileListLiveData.kt`·`ArchiveFileSystemProvider.kt`는 상위 저장소 코드다. 바꾸는 줄을 최소로 하고 판단은 순수 함수로 뺀다(#29 C-2와 같은 방침).
- **A-1**: 각 파일 시스템은 "경로가 없음"을 `NoSuchFileException`으로 알린다고 가정한다. 다른 예외로 알리는 파일 시스템에서는 REQ-69-05(B3)로 동작한다 — 지금보다 나빠지지 않는다. 루트·원격 프로세스 경로는 예외를 직렬화해 넘기므로(`provider/remote/ParcelableException.kt:24-34`) 형이 유지된다고 본다(확인은 HLD·LLD).

### 4.2 알려진 한계
- **L1**: 로컬 감시는 파일이 지워지면 inotify watch가 없어진다(`provider/common/WatchServicePathObservable.kt:74-76`, `key.reset()` 실패 시 종료). 같은 경로에 파일을 다시 만들어도 자동으로 다시 읽지 않는다 — 사용자가 당겨서 새로 고쳐야 한다. 폴더도 같다.
- **L2**: 감시를 지원하지 않는 원본(예: 원격 서버에서 다른 프로그램이 지운 경우 — 원격 변경 알림은 이 앱의 작업에서만 나온다, #29 SRS 1.3)은 지금처럼 다시 읽기 계기가 올 때까지(명시 새로 고침 등) 예전 목록이 남는다. 그 다시 읽기가 없음 실패면 REQ-69-03을 따른다.
- **L3**: 원인 조사의 재현은 HOT 시작(프로세스 생존)이었다. 진짜 새 프로세스(COLD)는 지금도 정상이다.

### 4.3 #29 설계 문서에서 바뀌는 점
- **REQ-29-06(b)** "표시 중인 목록을 그대로 둔다": 실패가 없음 실패면 적용하지 않는다(REQ-69-03). 다른 실패는 그대로.
- **REQ-29-07** "명시 새로 고침 결과가 실패면 토스트": 없음 실패면 토스트 대신 가운데 오류 글(목록이 비므로 기존 분기, `FileListFragment.kt:796-804`).
- **REQ-29-11** "감시를 지원하지 않는 경로(압축 파일 안)는 T4~T7만 적용": 압축 파일 안도 원본 파일 감시를 지원하므로(REQ-69-01) T1~T3이 적용된다. 원본 경로가 감시를 지원하지 않을 때만 T4~T7.
- **#29 HLD K1** 결과 게시 `Failure(valueCompat.value, e)`: 없음 실패는 `Failure(null, e)`. **K5** "감시 미지원(압축)이면 T1~T3이 생기지 않는다": 압축도 원본 감시를 통해 T1이 생긴다.
- #29 SRS(REQ-29-06·07·11)·HLD(K1·K5)에 이 브랜치에서 변경 이력 행과 해당 행의 주석을 단다(요구사항 ID·번호는 바꾸지 않는다).

## 5. 규격 근거 (부록 S)
해당 규격 조항 없음. 사용자에게 보이는 결과가 바뀐다(없음 실패 때 예전 목록+토스트 → 오류 화면) — 근거는 오너 결정(2026-11-19). 규격 편차는 없다.

## 6. 수동 확인 절차 (AVD만)
증거 폴더의 `repro.sh`와 같은 방식(adb, `Medium_Phone_API_36` 등 AVD). `t.zip` 안에 `d/a.txt`, `b.txt`.
- **V1 HOT, 압축**: VIEW intent로 `t.zip` 열기 → 목록 확인 → 앱을 연 채(또는 홈으로만 보내고 프로세스 생존 확인) `adb shell rm …/t.zip` → 몇 초 안에 오류 화면(예전 `d`, `b.txt` 없음, 가운데 `NoSuchFileException`). 홈 → 같은 intent로 다시 열기 → 오류 화면. 압축 안 `d/`에서 시작해도 같음. 수정 전 빌드에서는 예전 항목이 남아야 한다(fail-before).
- **V2 COLD, 압축**: `am force-stop`으로 프로세스를 실제로 끝낸 뒤(`pidof` 빈 것 확인) 삭제 → 다시 열기 → 첫 화면부터 오류(지금과 같음).
- **V3 로컬 폴더**: 폴더 `F`(항목 있음)를 보이게 두고 `adb shell rm -r F` → 당겨서 새로 고침(명시, 결정적 확인) → 오류 화면, 토스트 없음(수정 전: 예전 목록 + 토스트). 보조 확인(비결정적): 새로 고치지 않아도 자식 삭제 알림으로 몇 초 안에 오류 화면이 되는지 — `F` 자신의 삭제만으로 알림이 오는지는 미확인이라 필수 판정에 쓰지 않는다. `F`를 다시 만들고 당겨서 새로 고침 → 목록(L1).
- **V4 정상 압축**: 원본이 있는 zip 열기·하위 폴더·뒤로 가기가 수정 전과 같음. 원본 zip을 같은 이름의 다른 zip으로 덮어쓰면 목록이 새 내용으로 바뀜(REQ-69-02).
- **V5 B3 유지**: #29 REQ-29-06 절차(읽기 권한 제거 등) 하나 → 예전 목록 + "Error" + 토스트 한 번(지금과 같음).
