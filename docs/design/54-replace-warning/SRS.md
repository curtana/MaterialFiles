## 1. 목적과 범위

### 1.1 목적
충돌 창에서 "교체"(영어 "Replace")를 고르면 쓰기 가능 백엔드는 일반 파일·폴더 원본의 경우 **새 내용을 쓰기 전에 기존 대상을 먼저 지운다**(#42 조각 0 조사 표 1열: 로컬 `provider/linux/LinuxCopyMove.kt:56-65`, 공급자 간 `provider/common/ForeignCopyMove.kt:43-45`, SFTP·SMB·FTP·WebDAV·문서 제공자 각각의 `*CopyMove.kt`). 심볼릭 링크 원본은 링크를 만들기 직전에 지우는 백엔드가 있다(`provider/common/ForeignCopyMove.kt:93-102`의 "cannot delete beforehand" 주석) — 이 경우도 새 링크를 만들기 전에 기존 대상이 없어지는 것은 같다. 복사·이동·압축 풀기가 도중에 끊기면(취소, 연결 끊김, 앱 종료, 쓰기 오류) 기존 대상은 이미 없고 새 내용은 불완전하다. 오너는 이 위험을 없애지 않고 안고 가되 사용자에게 알리기로 했다(2026-11-04). 지금 창의 설명은 "내용을 덮어쓴다"고만 해서(`res/values/strings.xml:235`, `res/values-ko/strings.xml:204`) 선삭제와 손실 가능성을 알 수 없다.

### 1.2 범위
- 같은 이름 충돌 창(`java/me/zhanghai/android/files/filejob/FileJobConflictDialogFragment.kt`)에 경고 문구 하나를 더한다.
- 경고가 보이는 충돌 종류의 규칙(2.1).
- 영어(`res/values/`)·한국어(`res/values-ko/`) 문자열.
- 한국어 교체 메시지 `file_job_replace_message_format`의 오역 고침(#58). 경고와 같은 창·같은 파일이라 함께 고친다.

### 1.3 범위 밖
- 기존 대상 선삭제를 없애는 일(임시 이름 복사 후 교체). 오너가 거절했다(#42).
- 충돌·오류 창의 새 버튼·선택지·확인 창. 새 선택지는 #55 설계에서 함께 정한다(#55 2026-11-19 코멘트). 이 작업은 버튼 수·이름·동작을 바꾸지 않는다.
- 영어·한국어 밖 로캘(#21, 일시정지). 다른 로캘은 영어 경고로 대체된다(Android 기본 리소스 대체).
- #58 밖의 기존 문구 고침(영어 문구, 합치기 문구 등).
- 앱이 백그라운드일 때 충돌 창 대신 뜨는 알림의 문구(2.2 결정 D3).
- 글 편집기 저장(`WriteFileJob`)의 제자리 덮어쓰기. 충돌 창을 거치지 않는다(#42 조사 "save 경로").

### 1.4 용어
| 용어 | 뜻 |
|---|---|
| 충돌 창 | 대상 폴더에 같은 이름이 있을 때 뜨는 `FileJobConflictDialogFragment` 창 |
| 교체 충돌 | 충돌 창의 긍정 버튼이 "교체"인 경우. 코드의 `isMerge == false`(`FileJobConflictDialogFragment.kt:310-314`) |
| 합치기 충돌 | 원본과 대상이 모두 폴더여서 긍정 버튼이 "합치기"인 경우(`isMerge == true`) |
| 폴더 판정 | 링크를 따르지 않은 속성(`attributesNoFollowLinks.isDirectory`)으로 본다. 폴더를 가리키는 심볼릭 링크는 폴더가 아니다(`FileJobConflictDialogFragment.kt:311-312`, `filejob/FileJobs.kt:1380-1381`) |

## 2. 기능 요구사항

### 2.1 충돌 종류별 경고 표시 (제안, 오너 확인 지점 O1)
교체를 고르면 기존 대상이 먼저 지워지는 경우에만 경고를 보인다. 코드상 충돌 창이 뜨는 경우와 결과는 다음과 같다.

| 원본 | 대상 | 지금 창 | 교체 선택 시 | 경고 |
|---|---|---|---|---|
| 파일(링크·특수 파일 포함, 폴더 아님) | 파일(폴더 아님) | 교체 창(`isMerge` false) | 대상을 먼저 지우고 복사(`FileJobs.kt:1403-1419` → `REPLACE_EXISTING` 1358-1360) | **보임** |
| 폴더 | 파일(폴더 아님) | 교체 창 | 대상 파일을 먼저 지우고 폴더를 만든 뒤 하위 항목을 복사(로컬 `LinuxCopyMove.kt:136-144`) | **보임** |
| 폴더 | 폴더 | 합치기 창(`isMerge` true) | 대상 폴더를 지우지 않고 그 안으로 들어간다(`FileJobs.kt:1411-1414`). 안의 이름 충돌은 각각 다시 충돌 창을 띄운다 | 안 보임 |
| 파일(폴더 아님) | 폴더 | 창 없음. 예외로 실패(`FileJobs.kt:1382-1385`) | 해당 없음 | 해당 없음 |

이유: 합치기는 기존 폴더를 지우지 않으므로 경고가 사실이 아니다. 합치기 안의 개별 교체는 그 충돌 창에서 경고가 보인다.

## 3. 비기능 요구사항
- **API 레벨**: minSdk 그대로. 새 API를 쓰지 않는다.
- **권한·루트**: 새 권한 없음. 루트·비루트, 모든 백엔드에서 같은 창을 쓰므로 같은 경고가 보인다(백엔드별 분기 없음). 압축 파일은 대상이 될 수 없어 해당 없음(#42 조사, `provider/archive/ArchiveFileSystemProvider.kt:142`).
- **접근성**: 경고는 충돌 창 레이아웃 안의 글자(`TextView`)로 넣어 TalkBack이 창 내용과 함께 읽게 한다. `getMessage`(창 메시지 겸 알림 본문)에는 넣지 않는다(REQ-54-06). 아이콘을 더하면 설명(`contentDescription`)이나 장식 표시를 단다.
- **테마·대비**: 기존 창 글 스타일·테마 색 속성만 쓴다. 새 색을 정의하지 않는다(테마 대비 작업 #27과 겹치지 않게). 대비는 기존 창 메시지와 같은 수준이다.
- **RTL**: 글자만 더하므로 기존 레이아웃 방향을 따른다.
- **크기**: 작은 화면·큰 글꼴에서도 창은 이미 스크롤 안에 있으므로(`FileJobConflictDialogFragment.kt:257-259`) 경고가 길어져도 버튼이 가려지지 않는다.

## 4. 제약과 가정
- **위험은 그대로 남는다.** 이 작업은 알리기만 하며 데이터 손실 가능성을 줄이지 않는다(오너 2026-11-04). `CHANGELOG.md:29`의 알려진 문제("#42, planned before 1.7.5")는 다음 릴리스 문서 동기화 때 "경고로 알림, 위험 유지(#54)"로 고친다(설계팀 릴리스 작업, 이 PR 아님).
- **경고 문구가 모든 백엔드에 참이라는 가정**: #42 조사 표에서 쓰기 가능한 모든 백엔드(로컬·루트·공급자 간·SFTP·SMB·FTP·WebDAV·문서 제공자)가 교체 시 새 대상을 완성하기 전에 기존 대상을 지운다(이 SRS에서 다시 확인한 곳은 로컬·공급자 간뿐이고 나머지는 #42 조사 기준). 경고는 "잃을 수 있다"는 가능성 표현이므로 지우는 시점이 백엔드마다 조금 달라도 참이다. 같은 로컬 파일시스템 안 이동은 선삭제 뒤 이름 변경이라 실제 위험은 작지만, 이름 변경이 실패하면 복사로 넘어가므로(`LinuxCopyMove.kt:261-293`) "잃을 수 있다"는 표현은 참이다.
- **#55와의 관계**: #55가 충돌·오류 창에 새 선택지를 더하면 이 경고 문구가 그 선택지와 맞는지 #55 설계에서 다시 본다. 이 작업은 #55를 기다리지 않는다.
- 다른 로캘 사용자는 영어 경고를 본다(`CHANGELOG.md:31`의 알려진 문제와 같은 성격).
- 수동 확인은 기기·에뮬레이터에서 한다. 오너 기기 설치는 미리 묻는다.
